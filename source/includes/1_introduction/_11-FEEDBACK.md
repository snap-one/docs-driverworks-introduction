# Feedback and Corrections

The DriverWorks documentation is built from public GitHub repositories under the [snap-one][1] organization, one repository per guide (for example, `docs-driverworks-api` or `docs-driverworks-proxyprotocol-mediaplayer`). The [DriverWorks landing page][2] lists every guide and its repository.

If you find something that is missing, wrong or unclear, please tell us. Corrections from driver developers help everyone who uses the SDK.

**Report a problem**

Open an issue in the repository for the guide that has the problem. Please include:

- the page URL, including the section anchor (for example, `.../docs-driverworks-proxyprotocol-mediaplayer/#generic-media-player-capabilities-allow_audio_pathing`)
- what is missing or incorrect
- the OS version you are developing against, if it matters
- the correct information, if you know it

**Propose a change**

If you already know the fix, you can submit it directly:

1. Fork the guide's repository.
2. Edit the Markdown files under `source/includes`. Each folder is one section of the page, and each file is one topic.
3. Open a pull request against the repository's default branch, describing the change and why it is needed.

The DriverWorks team reviews issues and pull requests. When a change is merged, the published guide is rebuilt automatically.

**Not a documentation problem?**

For problems with the OS, a proxy or a Control4 driver itself, rather than with the documentation, please contact your Snap One developer support contact.
